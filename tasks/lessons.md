# Lessons

- 다른 브랜치의 기능을 이식할 때는 사용자가 부르는 기능명만 믿지 말고 실제 라우트와 컴포넌트 연결을 함께 확인한다. 이번 `main`은 `/viewer`와 `/mobile`을 분리했으므로, 조사 결과를 기록한 뒤 사용자가 명시한 `/viewer` 주소에 모바일 동작을 배치했다.
- 모바일 다중 영상 화면은 보이지 않는 페이지의 player를 마운트하지 않는다. 화면당 최대 연결 수를 제한해야 데이터 사용량과 브라우저 디코더 부담이 카메라 총수에 따라 증가하지 않는다.
- 주기적으로 갱신되는 카메라 목록의 선택 상태는 배열 인덱스가 아니라 안정적인 `streamName`으로 유지한다. 제거·비활성화 시에는 fullscreen과 orientation 상태까지 정리한 뒤 안전한 목록 화면으로 복귀한다.
- 로컬 Go 도구가 없는 작업 환경에서는 `go.mod`와 같은 버전의 격리된 도구 체인으로 전체 테스트와 빌드를 검증하되, 실제 daemon이나 카메라 런타임은 건드리지 않는다.
- Slim tunnel의 native password 지원은 CLI 플래그 존재만으로 가정하지 말고 계정 등급에서 실제 생성 가능 여부를 확인한다. Free 계정에서는 loopback 전용 Basic Auth 게이트웨이를 앞에 두고, public Origin과 upstream Host가 달라지는 WebSocket·동일 출처 검사까지 검증한다.
- 사용자가 특정 대상 브랜치에 기능 반영을 요청했다면 작업 브랜치의 커밋·푸시만으로 완료 처리하지 않는다. 대상 브랜치가 기능 커밋을 실제로 포함하고 원격 SHA가 일치하는지 확인한 뒤 반영 완료를 보고한다.
