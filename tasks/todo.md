# Mobile `/viewer` 작업 계획

## 사양과 기준선

- [x] 작업 전 브랜치/변경 상태를 확인하고 기존 사용자 파일을 보존한다.
- [x] 로컬 `main`(21e1e24)에서 `/viewer`, `/mobile`, 모바일 컴포넌트, 스트림 재생 방식을 확인한다.
- [x] CamStation 2.0의 카메라 DTO, 공개 스트림 선택, SPA 라우팅, 재생 복구 훅을 확인한다.
- [x] `/viewer` 제품 동작과 비목표를 `docs/superpowers/specs/`에 기록한다.

## 구현

- [x] 콘솔 셸을 거치지 않는 최상위 `/viewer` 라우트를 추가한다.
- [x] 활성 카메라를 4개씩 2×2로 보여주고 좌우 스와이프/페이지 표시를 제공한다.
- [x] 타일 선택 시 단일 카메라 상세 보기와 이전/다음/닫기 제어를 제공한다.
- [x] 전체화면 진입/종료, 모바일 가로 방향 요청, iOS 네이티브 전체화면 대체 동작을 제공한다.
- [x] 목록에서는 live 출력, 상세/전체화면에서는 focus 출력을 우선하고 기존 WebRTC→MSE 복구를 재사용한다.
- [x] 로딩/오류/빈 목록과 카메라 제거·재정렬 시 안전한 상태 복구를 구현한다.
- [x] 페이지 전용 스타일을 추가하되 기존 `/live` 및 콘솔 스타일에는 영향을 주지 않는다.

## 검증

- [x] 페이지 분할, 스와이프 임계값, 페이지 보정 모델의 단위 테스트를 추가하고 실행한다.
- [x] `/viewer`가 전용 페이지에 연결되는지 정적 라우트 검증을 추가한다.
- [x] `web` 테스트와 lint를 통과시킨다.
- [x] 프런트엔드 빌드 후 Go 전체 테스트와 daemon 빌드를 통과시킨다.
- [x] 생성된 embedded SPA가 `/viewer` 직접 요청에 응답하는지 확인한다.

## 검토

- `main`의 모바일 UX(`/mobile`)를 2.0의 요청 주소 `/viewer`로 옮기고, 콘솔/`/live` 라우트는 변경하지 않았다.
- 모바일 목록은 현재 페이지의 최대 4개 스트림만 연결하며 상세/전체화면 전환 시 목록 스트림을 정리한다.
- 카메라 식별은 배열 인덱스 대신 `streamName`을 사용해 10초 재조회 중 잘못된 카메라로 바뀌지 않게 했다.
- 웹 단위 테스트 56개, lint, Vite 빌드, Go 전체 테스트, daemon 빌드가 통과했다.
- embedded SPA의 `/viewer` 직접 요청이 HTTP 200, `Cache-Control: no-store`, app root HTML을 반환함을 테스트했다.
- 실제 모바일 기기 브라우저와 실카메라 영상 제스처 확인은 운영 배포 범위에 포함하지 않았다.

## Slim 임시 공유

- [x] Slim 설치 버전, 기존 도메인/터널, 리스닝 포트와 공유 옵션을 확인한다.
- [x] 기존 CamStation 런타임이나 실제 카메라 서버가 연결되어 있지 않음을 확인한다.
- [x] 현재 빌드를 격리된 preview 포트에서 시작하고 `/viewer` 응답을 확인한다.
- [x] Slim Free 계정의 native password 제한을 우회하지 않고, 로컬 Basic Auth 게이트웨이를 통해 짧은 TTL의 public tunnel을 생성한다.
- [x] 외부 HTTPS 응답, 만료 시각, 보호 상태와 targeted stop 명령을 확인해 사용자에게 전달한다.

Slim 공유 검토:

- CamStation upstream은 `127.0.0.1:20080`, 인증 게이트웨이는 `127.0.0.1:20081`에만 바인딩했다.
- Slim 0.9.3 Free 계정의 native password 기능은 Pro 전용이므로, 제공된 비밀번호의 bcrypt hash를 사용하는 임시 Caddy Basic Auth 게이트웨이를 적용했다.
- Slim tunnel의 첫 방문 경고를 통과한 뒤 미인증 요청은 401, 인증된 `/viewer`와 `/api/health`는 200을 반환했다.
- public Origin을 사용한 `/player/api/ws` 요청이 origin 검사를 통과하고 등록되지 않은 stream 단계에서 거부됨을 확인했다.
- 터널은 2026-08-09 15:12:48 KST에 자동 만료되며 `slim stop cold-fin`으로 조기 종료할 수 있다.
