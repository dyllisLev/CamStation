# 녹화 시작 지연과 직접 MP4 길이 수정

사용자가 2026-09-10 KST에 재시작 직후 녹화 시작 대기와 직접 MP4 길이 표시를
수정하도록 요청했다. 기존 영상·음성 내용과 절대시각을 보존하며 검증 후 배포한다.

## 확인된 문제

- 배포 직후 첫 완성 파일 8개에서는 음성이 영상보다 0.067~3.823초 먼저 기록됐다.
  이후 연속 녹화의 대표 8개에서는 같은 선행 패턴이 없었다. 이 수치는 첫 패킷의
  시각 차이이며, 실제 동작과 소리의 동기 오류를 의미하지 않는다.
- 녹화는 원본 영상 복사이며 첫 키프레임을 기다린다. FFmpeg 5.1.7의 초기 잘못된
  시각 패킷을 제외하기 위해 nobuffer를 사용한다. 불필요한 입력 분석 대기를 줄일
  수 있는지는 같은 RTSP 입력에서 측정한다. 키프레임이 없는 영상을 만들거나
  원래 시각을 변경해 시작 시간을 앞당기지 않는다.
- 직접 MP4 응답의 단순 epoch 정규화는 일부 파일의 전체 길이를 잘못 표시한다.
  합성 11.029초 파일이 13.043초로 표시되고, 실제 파일에서도 같은 종류의 오류가
  있다. 종료 이벤트 측정에서는 해당 차이만큼 화면이 멈추지 않았다.

## 수정 계약

1. 초기 분석 및 키프레임 대기의 피할 수 있는 부분을 줄인다. 영상 재인코딩이나
   카메라 설정 일괄 변경을 기본 해결책으로 사용하지 않는다.
2. 직접 재생과 다운로드는 실제 미디어 끝에 맞는 길이와 정상적인 처음·중간·끝
   탐색을 제공한다. 영상·음성의 상대 시각, B프레임 표시 순서와 패킷 내용은 유지한다.
3. 저장 원본과 HLS 조각, 절대 PRFT, DB 녹화 범위, 백업·삭제 보호는 보존한다.
   필요하면 직접 MP4 응답의 컨테이너 구조를 바꿀 수 있으며, 응답의 바이트 길이와
   Range/Seek는 그 구조에 맞춰 정확해야 한다.
4. 과거 일반 MP4와 상대시각 fMP4의 호환성을 유지한다. 요청마다 전체 영상 재인코딩
   또는 영구 복사본을 만들지 않는다.

## 완료 기준

- FFmpeg 5.1.7의 H.264·HEVC RTSP 시작 비교에서 초기 영상 지연 개선을 측정하고,
  정상 프레임·시각·PRFT·파일 전환과 음성 조건을 확인한다.
- 직접 MP4의 합성 및 실제 파일에서 패킷 시각·내용 보존, 브라우저 길이·탐색·종료,
  Range 및 기존 파일 호환 검증을 통과한다. 종료 지연은 이벤트 시각으로 측정한다.
- 변경한 백엔드의 필수 검사와 전체 Go 검사·daemon build를 통과한다.
- 운영 배포는 검증한 commit/image가 일치하고, DB와 기존 종료 녹화 및 신규 녹화
  8개·라이브 8대가 정상임을 확인한다. 운영 녹화 원본을 복구 명목으로 재작성하지 않는다.
