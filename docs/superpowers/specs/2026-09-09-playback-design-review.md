# 공통 재생 설계 독립 검토

날짜: 2026-09-09. 범위: 설계 검증 및 문서 보완. 제품 구현·테스트 실행·운영 변경 없음.

검토 대상: [화면→백엔드 분석](2026-09-09-playback-screen-to-backend-analysis.md), [구현 계획](../plans/2026-09-09-playback-screen-to-backend-plan.md).

## 1차 리뷰 기록 — 이후 축소 계획으로 대체

아래 D01~D12는 당시 발견 기록이다. 현재 작업 지시로 재사용하지 않으며, 구현·검증 범위는 수정 실행 계획과 이 문서의 2차 리뷰 결과를 따른다.

## 검토 방법과 판정

별도 에이전트 두 명이 독립적으로 검토했다. 한 명은 현재 화면 소스와 4화면 와이어프레임에서 이벤트 누락을 찾았고, 다른 한 명은 과개발·과테스트·과검증 및 서버/클라이언트 미정 계약을 검토했다. OP가 핵심 지적을 소스와 사용자 요구에 대조해 채택하고 문서를 수정했다. 검토자는 자신의 지적 반영 부분만 한 차례 다시 읽었다. 후속 검토에서 남은 두 문구(탐색 날짜와 재생 일시 구분, live 초기 자동 연결)는 OP가 바로잡았다.

초안은 큰 재생 흐름을 담았지만 **컴포넌트 이벤트 대장으로 쓰기에는 누락이 있었다.** 아래 12개 사항을 보완했다. 기존 집중 보기 재사용 및 영상 더블클릭 줌 초기화 유지에는 변경이 없다.

## 과개발 방지 경계

- 기존 집중 보기·줌 제스처는 재개발하지 않는다.
- 별도 장애 복구 시스템은 만들지 않는다. 새 playback 모드 보고와 기존 reconnect의 허용 문서 보존 판정만 최소 수정한다.
- 공통 모듈 이름과 세 가지 저장 모델은 논리 책임이다. 그 수만큼 물리 파일·클래스·테이블을 미리 만들지 않는다.
- 코덱 파생본은 실제 보관 코덱이 대상 런타임에서 재생되지 않을 때만 구체화한다.
- AI 이벤트·썸네일·북마크·별도 비동기 카메라 모드·신규 서버 권한 체계는 이 검토로 범위를 추가하지 않는다.

## 축소하지 않은 필수 검증

정확한 packet→fragment 시각 대응, 녹화 중 decode, 파일 rollover, 불완전 조각 비공개, 과거 MP4 호환, 최소 복구·백업 보호는 기능 성립 조건이다. 과검증이라는 이유로 제거하지 않는다. 같은 사실을 플랫폼/단계마다 반복 검증하지 않도록 책임을 나눴다.

컴포넌트 이벤트는 E01~E36 및 분석 문서 10절 대장에 연결했다. 번호 수는 기능 수나 테스트 수가 아니다. 기존 유지 입력은 기존 구현·검사를 재사용하며, 변경된 의미를 확인하는 대표 시나리오만 추가한다.

현재 검토는 정적 설계 검토다. 남은 기술 결정은 실제 시각 anchor 추출, 코덱 지원, 지연·동기 오차 측정이며 구현 선행 실험에서 해결한다. 이번 문서 검토로 이 항목이 검증됐다고 주장하지 않는다.

후속 사용자 제약: 검증 환경은 로컬과 테스트 PC, 실제 카메라는 최대 2대다. 이전 8대 실측 조건은 폐기하고 기존 중계 입력 공유 및 로컬 합성/녹화 소스 사용으로 송출 부하를 줄인다.

최신 사용자 정정: 로컬에서도 부하/스트레스/자원 벤치마크는 하지 않는다. 연결 복구는 테스트 측 수신을 닫았다 다시 연결해 확인한다. 성능 최적화는 실제 운영 문제가 생길 때 다루며 완료 조건에 성능 수치를 추가하지 않는다.

최종 범위 정정: 요청 기능과 실제 운영을 막는 구체적인 문제만 출시 전 필수로 한다. 운영 중 모니터링하며 조정 가능한 성능·튜닝·드문 장애·관측 확장은 후순위로 제외한다. 이 기준이 위 검토에서 제안한 작업·검사보다 우선한다.


## 2차 리뷰 — 구현·검증 범위 직접 축소 후

사용자 요청에 따라 실행 계획을 다시 작성하고 별도 에이전트가 한 차례 재리뷰했다. 기존 계획에 우선 문구만 덧붙이지 않고, 포괄적인 복구·신규 telemetry·버전 조합·정밀 튜닝과 추가 검증 의무를 본문에서 제거했다.

현재 필수 범위는 B 녹화 화면, 라이브 공통시각 재생, 기존 집중 보기 상태 유지, LIVE 복귀, 녹화 중 완성 조각 재생, 기존 녹화 보존이다. 조건부로만 보완하는 항목은 실제 코덱 재생 불가나 기존 자동 복구가 재생을 중단시키는 등 구체적인 운영 차단 문제다.

리뷰 결과: 핵심 요구와 E01~E36의 이벤트 연결에서 추가 누락은 발견되지 않았다. 남은 문구 충돌 5개는 OP가 모두 수정했다.

| 지적 | 반영 |
| --- | --- |
| 고정 해상도/DPI별 검증 의무 | 실제 로컬·테스트 PC 화면과 목록 드로어 동작만 확인 |
| 코덱 파생본 자원 검증이 완료 조건 | 실제 재생·시각 매핑만 확인 |
| 날짜 탐색에서 cursor 초기화가 재생커서와 혼동 | 목록 페이지 cursor만 초기화, 실제 재생 시각·커서는 유지 |
| 모듈 표의 드리프트/상태 보고 개발 의무 | 공통 시각 이동·재연결 합류 및 기존 전체화면 bridge로 한정 |
| 폐기된 P3 참조 | 실제 구현에 필요한 최소 스키마 선택으로 수정 |

검증은 로컬·테스트 PC와 실제 최대 2대 카메라의 기능 확인이다. 연결 복구는 수신 측 연결 해제/재연결만 확인한다. 부하·장시간 반복·crash 주입·성능 수치 게이트는 없다. 통과 후 운영을 막는 구체적 문제가 없으면 종료한다.

이번 재리뷰에서는 문서만 수정·확인했으며 제품 코드·제품 테스트·운영 변경은 없다.
