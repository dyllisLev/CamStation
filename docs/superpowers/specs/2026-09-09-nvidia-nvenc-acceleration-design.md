# 선택적 NVIDIA NVENC H.264 설계

상태: 구현 전 제안. 2026-09-09 KST 인수인계 문서와 현재 소스를 대조한 계획이며, 이번 작성에서는 장비 상태를 재검증하지 않았다.

## 목표와 범위

선택한 카메라 출력의 H.264 인코딩 CPU 사용량을 줄인다. CPU가 기본이며 녹화·입력 릴레이·live warm의 stream copy 계약을 유지한다. GPU 디코딩, GPU 스케일링, HEVC 인코딩, 호스트 드라이버 교체는 범위 밖이다. 개발 CT 102 검증을 먼저 완료하고 운영 CT 113 배포는 개발 검증 후 진행한다. 후속 사용자 요청에서 운영 배포 및 Proxmox CPU 사용률 전후 비교가 명시적으로 승인되었다.

## 정책과 상태

이 계획은 카메라 자체의 인코딩 설정을 변경하지 않는다. 카메라가 보낸 압축 영상을 서버가 그대로 중계·녹화할 수 있으면 copy를 유지한다. 서버에서 해상도/FPS/코덱 변환이 필요한 출력만 기존 CPU 재인코딩을 GPU 재인코딩으로 바꾼다. 카메라 프로파일 조정으로 서버 변환을 없애는 방식은 별개의 접근이다.

- 기존 출력별 `videoMode=auto|copy|h264`에 독립적인 `videoEncoder=cpu|nvenc`를 추가한다. 카메라 단위가 아니라 recording/live/focus 출력 단위로 설정한다.
- 누락 필드, 기존 DB, 기존 applied snapshot은 `cpu`로 정규화한다. 알 수 없는 값은 저장 전에 거부한다.
- `copy`에는 `cpu`만 허용하며 UI에서도 GPU 선택을 비활성화한다. `auto+nvenc`라도 기존 판정이 copy이면 복사를 유지하고 GPU 세션을 소비하지 않는다.
- desired/applied snapshot에는 선택값을 보존한다. 실제 인코더와 CPU 복귀 사유는 별도로 보고한다. H.264 코덱 검출만으로 NVENC 실행 성공을 주장하지 않는다.
- 일시적인 GPU 장애로 사용자의 desired 정책을 CPU로 덮어쓰지 않는다. 프로세스 재시작 뒤에는 오래된 GPU 성공 상태를 그대로 신뢰하지 않고 다시 검사한다.

## GPU 실행과 안전한 복귀

- 전역 `h264` CPU 프리셋은 유지하고 별도 `h264/nvenc` 프리셋을 선택한다. 인코딩만 GPU로 보내고 기존 CPU 필터를 유지한다. NVENC는 `-rc vbr -cq 23 -b:v 0`로 기본 2 Mbps 제한에 따른 4K 화질 저하를 피한다. 동일한 4K·20fps·5초 원본 비교에서 CPU SSIM 0.979986/36.181 dB, 이 설정은 0.980144/36.301 dB였으며 비트레이트는 18.620/20.954 Mbps였다. 이는 해당 표본의 품질 근거이며 모든 장면의 동등성을 보장하지 않는다.
- 최대 3은 하드웨어의 보장 용량이 아닌 보수적 운영 상한이다. 같은 카메라의 live/focus 동시 실행도 각각 센다.
- 여기서 세션은 서버 GPU의 동시 인코딩 작업 하나다. 카메라 수·시청자 수·상태 조회 횟수가 아니다. live/focus도 각각 실제 GPU 재인코딩을 실행할 때만 별도 세션을 쓴다. 일반 상태 조회나 기존 출력 ffprobe는 별도 GPU 인코딩 세션을 만들지 않는다. 다만 on-demand 출력을 깨우면 그 출력의 인코딩 작업이 시작될 수 있다.
- 구성 생성 시 실제 변환이 필요한 활성 출력들을 camera ID, purpose 순서로 정렬해 최대 3개에 GPU를 배정하고 나머지는 `session_limit` 사유와 함께 CPU로 실행한다. on-demand도 예약에 포함해 요청 시 초과를 막는다.
- 구성상의 제한에 더해 실제 NVENC 자식 프로세스 시작 경계에서 원자적 3슬롯 제한을 둔다. 검사·중복 실행·교체 중 구/신 프로세스도 포함하며, 슬롯은 자식 종료 확인 뒤 반환한다. 별도 CamStation 인스턴스/다른 GPU 소비자가 있는 환경은 전용 사용 여부를 배포 전 확인한다.
- 실제 합성 인코딩 검사에 시간 제한을 두고 장치·권한·라이브러리·API·인코더 오류를 구분한다. 실행 중 슬롯 부족/인코더 초기화 실패/장치 장애는 해당 출력만 CPU로 재시작한다. 일반 원본 연결 장애를 GPU 장애로 오인하지 않는다.
- 자동 복귀는 전체 go2rtc 재시작에 의존하지 않는다. 이를 위해 출력 FFmpeg 실행을 관리하는 작은 supervisor를 우선 검증한다. 종료 신호 전달, 자식 회수, CPU 인수, 상태 보고가 입증되지 않으면 운영 전환 조건 미충족이다.
- 복귀 후에는 같은 실행 회차에서 NVENC 재시도를 반복하지 않는다. 명시적 재검사/재적용으로 재시도하며 검사에도 동일한 세션 제한을 적용한다.

## 패키징과 공개 정보

GPU 이미지는 기존 CPU 이미지와 구분한다. glibc 기반 별도 Dockerfile을 우선 검증하고 FFmpeg `n5.1.7`, headers `n11.1.5.3`, NVIDIA 사용자 공간 라이브러리 `470.256.02`를 출발점으로 삼는다. 태그뿐 아니라 소스 commit/checksum, 기반 이미지 digest, 패키지 출처·버전을 고정한다. 이 버전 조합은 인수인계의 단기 실험 결과이며 제품 전체 호환성 보장은 아니다.

공개 상태에는 선택 인코더, 확인된 실제 인코더, 검사 시각, 제한된 오류 코드만 제공한다. 원본 URL, 내부 주소, 라이브러리 경로, 전체 명령행/stderr는 공개하지 않는다. 내부 생성 설정에 필요한 기존 비공개 입력은 유지하되 API·로그·검증 보고서로 유출하지 않는다.

## 완료 기준

CPU 회귀, 선택 출력 NVENC 실행, 세션 상한, GPU 장애 시 출력 단위 복귀, 브라우저 재생, 녹화 무결성, 이미지 재빌드, 이전 CPU 이미지 복귀를 CT 102에서 확인해야 개발 검증 완료다. 상세 순서와 증거는 [구현 계획](../plans/2026-09-09-nvidia-nvenc-acceleration.md#실행-계획)에 따른다.
