# 녹화 시작과 MP4 길이 수정 실행 계획

기준: [수정 계약](../specs/2026-09-10-recording-start-and-mp4-duration.md).

1. 입력 시작 개선: 같은 로컬 RTSP 입력에서 기존 입력 옵션과 불필요한 FPS 분석을 줄이는 후보를
   비교한다. nobuffer·epoch·PRFT 보호를 유지한 채 유효한 후보만 recorder에 반영한다.
2. 직접 MP4 수정: 기존 메타데이터 값만 바꾸는 실패한 실험을 반복하지 않고 일반 MP4
   구조의 정확한 시간 모델을 확인한다. 미디어 바이트를 복사하지 않는 가상 파일
   방식으로 호환 응답을 만들고 parser·Range·브라우저 검증을 추가한다.
3. 통합: OP가 HTTP 계약·영상/음성 시각·과거 파일 호환을 검토한다. 독립 검증과 전체
   Go 검사·빌드 후 구현 상태 문서를 갱신한다.
4. 배포: 직전 운영 상태와 DB 백업을 확보하고 Forgejo/OpenShip 경로로 배포한다.
   정확한 image/commit과 health, 기존 파일 종료 및 신규 8대 녹화·라이브를 확인한다.

## 구현과 측정

- recorder에 `-fpsprobesize 0`만 추가했다. codec 발견에 필요한 기본 분석 시간·바이트
  한도와 nobuffer, 원본 복사, epoch 및 PRFT를 유지한다.
- FFmpeg 5.1.7 합성 RTSP에서 첫 영상은 H.264 2.551→0.496초, HEVC
  5.032→1.058초였다. 실제 HEVC 카메라의 키프레임 직전 비교는 첫 영상
  5.316→1.287초, 첫 완성 조각 9.607→5.601초였다. 후보가 정상 영상 80프레임을
  더 확보했고 공통 136프레임의 디코드 해시는 동일했다. 음성·영상 디코드와 PRFT,
  인덱스 검증을 통과했다. 양쪽이 같은 키프레임을 잡은 첫 비교에서는 개선이 없었다.
- 실제 카메라의 키프레임 간격은 약 2~8초다. FPS 분석으로 놓치던 키프레임을
  줄여도 다음 키프레임과 조각 완성을 기다리는 시간은 남는다.
- 직접 재생·다운로드는 표준 MP4의 sample table·edit list·명시적 duration을
  메모리에 만들고 payload는 저장 원본에서 읽는 가상 파일로 제공한다. 원본 파일,
  HLS, DB 시각과 PRFT의 절대 NTP는 바꾸지 않는다. 응답 크기·Range는 새 구조를 따른다.
- 실제 29분 51.859초 파일은 기존 브라우저 길이 1795.681836초에서
  1791.858497초로 수정됐다. 합성 11.029333초 파일도 같은 길이로 표시됐다.
  처음·중간·끝 탐색과 정상 종료를 확인했다. 이전에 보고한 마지막 화면 정지는
  [재측정에서 정정한 내용](../../playback-deployment-2026-09-09.md)이며 이번 수정의
  확인된 대상은 길이 표시 오류다.

## 검증

- 전체 `go test ./...`와 daemon build를 통과했다. FFmpeg 5.1.7의 media 검사와
  녹화 검사도 통과했다. 컨테이너에 공유되지 않은 임시 경로와 RTSP 네트워크 차단으로
  실패한 실행은 환경을 바로잡아 재검증했다. 로컬 1초 GOP RTSP 검사는 첫 영상
  2.055초, 조각 인덱스·파일 전환·성장 중 디코딩 정상으로 통과했다.
- 합성 음성 선행/영상 선행/B프레임/음성 없음/signed CTS에서 원본 소스 PTS와
  지정 입력 지연·종료 시각을 기준으로 길이·상대 시각·payload를 검증했다.
  FFprobe가 마지막 AAC/HEVC 패킷 길이를 추정하는 경우에는 trun/stts의 명시 길이를
  확인했다. 길이 0인 유효 AAC 샘플도 개수·바이트·sample table에 보존된다.
- HTTP 직접 재생·다운로드 동일 응답, 새 Content-Length, 앞·중간·끝 Range와
  범위 초과 416, 메타데이터 교체 경계를 가로지르는 읽기와 원본 불변을 확인했다.
- 독립 검토에서 상대시각 fMP4 두 종류의 거부 회귀를 발견하고 수정 전 실패→수정 후
  원본 바이트 동일을 확인했다. 무작위 ReaderAt 10,000건과 실제 HEVC 216/AAC 88개
  payload·시각·전체 디코딩을 통과했고 추가 핵심 결함은 없었다.

## 운영 검증과 로딩 보완

- 첫 수정 `a1d5764`는 2026-09-10 09:02 KST에 CI/OpenShip 배포가 성공했다.
  exact image·healthy·재시작 0, DB·마운트·라이브 8대·NVENC 2개·백업 상태를 확인했다.
  기준 시점과 교체 직전의 총 16개 녹화가 ready·크기 일치·영상/음성 ffprobe를
  통과했고, 신규 8개 녹화의 파일·인덱스가 증가했다.
- 운영 HTTP에서 실제 30분 파일을 재생하자 메타데이터 로딩이 20초 안에 끝나지 않았다.
  응답의 파일 구조에 남긴 여러 mdat 때문에 Chrome이 조각마다 Range를 순서대로
  요청했다. 같은 파일에서 요청마다 50ms를 지연한 비교는 기존 구조 16.032초,
  brand만 변경 15.828초, 단일 mdat 구조 0.071초·요청 1개였다.
- 이에 PRFT 메타데이터를 앞에 모으고 기존 파일의 나머지 영역을 하나의 mdat로
  감싸 제공한다. 원본 조각 헤더는 샘플 사이의 읽히지 않는 영역으로 보존하고,
  실제 영상·음성 샘플 위치만 새 메타데이터 길이에 맞춰 연결한다.
- 최종 명시 길이의 16바이트 mdat 헤더에서 동일 브라우저 검사는 0.071초·요청 1개,
  올바른 1791.858497초 길이와 처음·중간·끝 재생 및 정상 종료를 확인했다.
  독립 검토에서 전체 원본 tail·모든 PRFT NTP·샘플 위치·Range를 재확인했다.

진행: 로딩 보완의 검증과 재배포 후 운영 브라우저의 길이·처음/중간/끝 재생을 확인한다.
