# 2026-09-09 녹화 재생 배포 기록

## 첫 배포와 롤백

Windows 운영 NUC에는 검증한 Viewer MSI 2.0.30을 설치했다. 설치된 실행 파일,
app.asar, 관리 서비스 해시는 테스트 PC의 MSI 설치 결과와 일치하며 설정과 클라이언트

서버 첫 배포 후 FFmpeg 5.1.7의 RTSP 입력에서 영상 시간축 손상을 확인했다.
입력 탐색 중 보관한 PTS/DTS 없는 선두 패킷과 이후 epoch 패킷이 섞여 MP4 영상
표본의 시간이 축소됐으며, 완성 조각 인덱스도 게시되지 않았다. 기존 TS/파일 입력
검사로는 재현되지 않았던 RTSP 경계다. 2026-09-09 22:06 KST에 이전
`220a588aa658b03a73bea21ac25a6f111246708c` 이미지로 롤백했다.
DB를 과거 백업으로 덮어쓰지 않았고, 해당 구간 8개 파일과 DB 행을 보존했다.
롤백 후 healthy, 재시작 0, SQLite 검사 정상, 녹화 8개 생성·증가를 확인했다.

## 수정과 검증 범위

- RTSP 입력에 `+nobuffer`를 적용해 탐색 중 보관한 선두 패킷을 버리고 실제
  timestamp가 있는 키프레임부터 기록한다.
- 트랙별 시작점을 각각 0으로 만드는 MP4 동작은 영상·음성 시간차를 잃으므로,
  모든 트랙의 epoch decode timestamp와 packet 기반 PRFT를 함께 보존한다.
- 재생 인덱스와 HLS는 첫 조각의 가장 이른 트랙 decode 시각을 공통 원점으로
  사용한다. 영상 시작 전 오디오는 HLS 시간에는 포함하지만 영상 보관 범위로
  표시하지 않는다. 첫 조각 이후 탐색도 같은 원점을 사용한다.
- 배포에 사용한 FFmpeg 5.1.7에서 합성 RTSP(H.264·HEVC), 조각 게시·파일 전환과
  명시적 2초 영상·음성 시작 차이 검사를 통과했다. Chrome HLS 첫 영상·중간 탐색·
  다음 파일 전환에 미디어 오류가 없었다. 기존 실제 중계 스트림 2개를 12.416초
  확인해 8개 파일, 246개 영상 프레임을 오류 없이 디코드했다. 실제 첫 파일의
  오디오 선행 987/1440ms도 인덱스에 보존됐다. 장시간·부하 시험은 실시하지 않았다.

## 직접 파일 재생과 다운로드

새 파일의 `/play`, `/download`는 저장 파일을 수정하지 않고 응답의 시간 메타데이터만
공통 영상·음성 원점으로 정규화한다. 패킷 내용, PRFT의 절대 NTP, 파일 길이와 바이트
위치는 보존해 Range 탐색을 유지한다. 기존 상대시각 fMP4와 일반 MP4는 원래 바이트를
그대로 응답한다. 저장·백업 원본과 HLS 조각은 변경하지 않는다.

Chrome 직접 MP4 재생에서는 오디오가 영상보다 먼저 시작하는 파일의 전체 길이를
길게 추론하는 한계가 남는다. 2.021초 오디오 선행 표본은 실제 미디어 끝 11.029초를
13.043초로 표시했고, 마지막 프레임을 약 2초 유지한 뒤 오류나 무한 대기 없이 종료했다.
첫 영상과 10초·파일 끝 근처 탐색, 영상·음성 시간차는 유지됐다. movie/track duration
설정과 random-access index 제거 실험에서도 같았다. 제품 B 화면과 공통 HLS 재생은
11.029초로 정상 처리하므로 별도 저장 형식 변경으로 확대하지 않았다.

## 손상 구간 복구의 한계

대상은 첫 배포 중 종료된 ready 녹화 ID 10950–10957이다. 원본을 별도 root 전용
백업에 보존하고, 영상 패킷 순서·내용과 원래 오디오 timestamp를 유지하는 후보를
만들었다. 영상 시간은 같은 카메라의 정상 파일과 메타데이터로 확인한 명목 FPS로
다시 구성한다. 손실된 원래 프레임별 수신 시각·간격이나 정확한 입 모양 동기는
복원했다고 주장하지 않는다. 새 PRFT를 꾸며 넣지 않으며 기존 파일 재생 경로를 쓴다.

복구는 파일별 원자적 교체와 DB `file_size` 갱신으로 제한한다. 녹화 시작·종료 시각,
상태, 백업 상태, 파일 권한·소유자·수정 시각은 유지한다. 따라서 일부 파일의 복구된
전체 미디어 길이가 기존 DB 종료 경계보다 약간 길 수 있다. 다운로드에는 전체
패킷을 보존하며, 보관 범위의 기존 종료 시각을 추정값으로 늘리지 않는다.
